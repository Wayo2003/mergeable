# Upgrade Dossier

Read a completed `.mergeable/runs/<run-id>/` folder and produce two output files:
- `dossier.html` — a polished, self-contained HTML report (opens offline in any browser)
- `pr-body.md` — a ready-to-paste GitHub PR description

## Inputs (all in the run folder)

| File | Required | Description |
|---|---|---|
| `triage.json` | yes | CVEs found, severity, exposure verdict, usage map |
| `breaking-changes.json` | yes | Structured breaking changes (from breaking-change-extractor skill) |
| `plan.md` | yes | Change plan with risk level per file |
| `checks-before.json` | yes | Test results before the fix |
| `checks-after.json` | yes | Test results after the fix |
| `diff.patch` | optional | Git diff of the changes made |

Collect the run folder path via `ask_followup_question` if not already provided.

## Steps

### 1 — Read all inputs

Use `read_file` to read each file in the run folder. Parse:
- `triage.json`: extract `vulnerabilities[]` (id, cve, severity, fixedIn), `exposure` (verdict, usageSites[])
- `breaking-changes.json`: extract each breaking change entry
- `checks-before.json` and `checks-after.json`: extract `passed`, `failed`, `failures[]`, `durationMs`
- `plan.md`: extract the list of files touched and risk levels
- `diff.patch`: read as raw text for per-file diff display

### 2 — Compute derived stats

Calculate:
- `cvesClosed`: number of vulnerabilities with a valid `fixedIn` version ≤ the target version
- `maxSeverity`: highest severity across all closed CVEs (CRITICAL > HIGH > MEDIUM > LOW)
- `callSitesFixed`: count of usage sites from `triage.json` that correspond to breaking changes that were addressed
- `filesTouched`: unique file count from `plan.md` or the diff
- `breakingChangesHandled`: count of breaking change entries with at least one diff hunk referencing them
- `testsBefore` / `testsAfter`: `passed` and `failed` counts from the checks files
- `durationMs`: time between checks-before and checks-after timestamps (or sum if available)

### 3 — Render dossier.html

Use the template at `.bob/skills/upgrade-dossier/templates/dossier.html` as the base.
Replace the following placeholder tokens with real data:

| Token | Replace with |
|---|---|
| `{{PACKAGE}}` | Package name (e.g. express) |
| `{{FROM_VERSION}}` | Version upgraded from |
| `{{TO_VERSION}}` | Version upgraded to |
| `{{RUN_ID}}` | The run folder ID |
| `{{GENERATED_AT}}` | ISO timestamp |
| `{{VERDICT_CLASS}}` | `verdict-green` if all tests pass, else `verdict-red` |
| `{{VERDICT_LABEL}}` | `Ready to merge` or `Needs attention` |
| `{{CVES_CLOSED}}` | Number of CVEs closed |
| `{{MAX_SEVERITY}}` | Highest CVE severity |
| `{{TESTS_BEFORE_PASS}}` / `{{TESTS_BEFORE_FAIL}}` | Test counts before |
| `{{TESTS_AFTER_PASS}}` / `{{TESTS_AFTER_FAIL}}` | Test counts after |
| `{{CALL_SITES_FIXED}}` | Call sites fixed |
| `{{FILES_TOUCHED}}` | Files touched |
| `{{BC_HANDLED}}` | Breaking changes handled |
| `{{DURATION_MIN}}` | Duration in minutes (rounded) |
| `{{CVE_ROWS}}` | HTML rows for the CVE table |
| `{{BC_ROWS}}` | HTML rows for the breaking changes accordion |
| `{{RESIDUAL_RISK}}` | Prose paragraph from plan.md residual risk section |
| `{{CHECKLIST_ITEMS}}` | `<li>` items for the reviewer checklist |

Write the rendered HTML to `<run-folder>/dossier.html` using `write_file`.

### 4 — Render pr-body.md

Use this template:

```markdown
## 🩹 Upgrade: {{PACKAGE}} {{FROM_VERSION}} → {{TO_VERSION}}

> Generated by [Mergeable](https://github.com/your-org/mergeable) on IBM Bob · Run `{{RUN_ID}}`

### Security
{{CVE_SUMMARY_MD}}

### Breaking changes handled ({{BC_HANDLED}})
{{BC_LIST_MD}}

### Tests
| | Before | After |
|---|---|---|
| ✅ Passing | {{TESTS_BEFORE_PASS}} | {{TESTS_AFTER_PASS}} |
| ❌ Failing | {{TESTS_BEFORE_FAIL}} | {{TESTS_AFTER_FAIL}} |

### Residual risk
{{RESIDUAL_RISK}}

### Files changed
{{FILES_LIST_MD}}

---
*Full dossier attached as a PR comment below.*
```

Write to `<run-folder>/pr-body.md` using `write_file`.

### 5 — Report

Confirm both files were written and output their paths. Summarise the verdict in one sentence.

## Quality rules

- The dossier.html must be fully self-contained (no external URLs, no CDN links).
- All CVE IDs must link to `https://osv.dev/vulnerability/<id>`.
- If checks-after.json shows any failing tests, the verdict banner must be `Needs attention` (red), not `Ready to merge`.
- Never fabricate test counts, CVE IDs, or file names — use only data from the input files.
- If a file is missing, note it as "not available" in the relevant section rather than inventing data.
